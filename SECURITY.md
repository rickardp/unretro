# Security Policy

## Supported Versions

| Version | Supported          |
| ------- | ------------------ |
| 0.1.x   | :white_check_mark: |

## Reporting a Vulnerability

If you discover a security vulnerability in unretro, please report it responsibly:

1. **Do not** open a public GitHub issue for security vulnerabilities.
2. Email the maintainer directly or use [GitHub's private vulnerability reporting](https://github.com/ricardolstephen/unretro/security/advisories/new).
3. Include a clear description of the issue, steps to reproduce, and any relevant sample files.

You can expect an initial response within 72 hours. Confirmed vulnerabilities will be patched and disclosed in a timely manner.

## Security Model

unretro is a **read-only** archive extraction library. It does not write files to disk or execute content from archives. The primary attack surface is malformed or malicious archive data.

### Built-in Protections

- **Decompression size limits**: All decompressed data is capped at `MAX_DECOMPRESSED_SIZE` (4 GiB) to prevent zip-bomb-style attacks.
- **Header sizes are not trusted for allocation**: A size declared in an archive header reserves at most 1 MiB up front; buffers grow only as data is actually decoded. Formats that must allocate the declared size in full (UDIF/NDIF disk images, RAR) reject sizes above `MAX_DECOMPRESSED_SIZE` first.
- **Cumulative output budgets**: Formats whose entries can point at the same stored bytes (HFS/MFS/HFS Plus forks, resource forks, iMUSE bundles) charge everything they copy out against a budget proportional to the input size (minimum 16 MiB), so aliased entries cannot multiply output. HFS Plus hard links copy nothing, so the content they yield together is bounded separately at 1024 times the volume size (minimum 16 MiB, maximum `MAX_DECOMPRESSED_SIZE`). UDIF/NDIF images additionally bound stored and compressed chunks by their backing size; zero-fill chunks are exempt so sparse images still open.
- **Cumulative nesting budget**: The per-container budgets do not compose across nesting levels: a container whose entries alias its own bytes is reopened once per entry at every level, and each level claims its own minimum allowance. The loader therefore counts every entry yielded by every container of one input against a single budget of 64 times the input size (minimum 8 GiB, twice `MAX_DECOMPRESSED_SIZE`), plus 4 KiB per nested container opened. When it is spent, no further nested container is opened and one `NestedContainerOpenFailed` diagnostic is reported. Files below a directory source are separate inputs.
- **Bounded structure traversal**: B-tree node links, directory parent chains, allocation chains and Huffman trees are walked with visited-set or step limits, so cyclic or over-deep structures end in an error rather than a hang or stack overflow.
- **StuffIt**: Parsed and decoded natively with no third-party decoder, from the format specification in `docs/stuffit/`. Classic records are strictly sequential and bounded by the archive length. StuffIt 5 entries are reached through stored offsets, so each entry is listed at most once, the extents of all listed entries together may not exceed the archive length, folder nesting stops at 64 levels and every name is held once however many entries lie below it (joined paths are bounded by 16 times the archive length), and each entry header is validated once however many links point at it; a chain that loops, overlaps or leaves the archive ends the listing with what was found so far. Every fork must decode to exactly its declared length and match its CRC-16 (for method 15 the CRC-32 inside its stream); a declared length that the packed bytes cannot produce is rejected before decoding for methods 1, 2 and 13, and a method 15 block longer than the output still owed is not held in memory. All forks of one archive are charged against a budget of 1024 times the archive length (minimum 16 MiB) before they are decoded. Encrypted forks, unsupported methods and forks failing any of these checks are never delivered, not even partially: the file (or only its resource fork) is skipped with a `ContainerEntriesSkipped` diagnostic while the readable files are still listed.
- **BinHex**: Decoded natively with no third-party decoder. Header, data-fork and resource-fork CRCs must match or the file is rejected; run-length expansion is produced only up to the fork lengths declared in the header, which together may not exceed `MAX_DECOMPRESSED_SIZE`.
- **ZIP**: Parsed and inflated natively with no third-party decoder. The central directory is authoritative; every entry must decode to exactly its declared size, which may not exceed `MAX_DECOMPRESSED_SIZE` and is also the decoder's output limit, and must match its stored CRC-32. Central headers are read from directory bytes that are really present, delimited by the declared directory size; the declared entry count is only a lower bound. Each entry read is charged (compressed size plus local header) against the archive length, so central headers that alias the same local data cannot multiply its output; entries beyond that total are skipped. Encrypted entries, entries on another disk, unknown compression methods and entries failing the size or CRC check are skipped with a `ContainerEntriesSkipped` diagnostic while the readable entries are still listed. Multi-disk archives are rejected.
- **GZIP**: Parsed and inflated natively with no third-party decoder. Only the deflate method is accepted and reserved header flags are rejected; the optional header CRC-16 and each member's CRC-32 and length trailer must match or the file is rejected. All members of a multi-member file are decoded, and their combined output may not exceed `MAX_DECOMPRESSED_SIZE`.
- **BZIP2**: Decoded natively with no third-party decoder, as a `.bz2` file, as ZIP method 12 and as UDIF disk image blocks. Every block CRC and stream CRC must match or the data is rejected, and nothing is delivered partially. All streams of a multi-stream file are decoded, and their combined output may not exceed `MAX_DECOMPRESSED_SIZE`; a ZIP entry or UDIF block is decoded with its declared size as the output limit and must reach exactly that size.
- **XZ / LZMA**: Decoded natively with no third-party decoder, as a `.xz` or legacy `.lzma` file, as ZIP methods 14 (LZMA) and 95 (XZ) and as UDIF disk image blocks. In a `.xz` stream the header, block header, index and footer CRCs, the index contents and every block's integrity check (CRC32, CRC64 or SHA-256) must match or the data is rejected, and nothing is delivered partially; reserved check types are rejected as unsupported. The LZMA2 and Delta filters are decoded; the BCJ (branch/call/jump) filters are rejected as unsupported. A legacy `.lzma` file is selected only by its extension, must end exactly at its end marker or declared size, and has no checksum, so its content is not authenticated. Match distances are checked against both the data decoded so far and the declared dictionary size, no window is allocated from the declared dictionary size, and the largest allocation driven by a header is the literal probability table (about 6 MiB for raw LZMA, 28 KiB under LZMA2). All streams of a multi-stream file are decoded, and their combined output may not exceed `MAX_DECOMPRESSED_SIZE`; a ZIP entry or UDIF block is decoded with its declared size as the output limit and must reach exactly that size.
- **TAR**: Parsed natively with no third-party reader. Members are strictly sequential, and a member's data is copied only once all of it is found present in the archive, so a declared size never allocates more than the archive holds; an archive with a file member larger than `MAX_DECOMPRESSED_SIZE` is rejected. Every header checksum is verified. pax extended headers and GNU long-name records larger than 1 MiB are treated as damage. A bad checksum, a truncated member or an oversized extension record ends the listing: an archive with no readable member before that point is rejected, otherwise the members already read are listed and the problem is reported with a `ContainerEntriesSkipped` diagnostic. Sparse members (old GNU and pax `GNU.sparse` 0.0, 0.1, 1.0) are expanded, with the output of all of them together charged against a budget of 1024 times the archive length, with no minimum, so nested archives cannot each claim an allowance; a sparse member over that budget or with an invalid map is skipped with the same diagnostic. A global pax `path` applies to every following member, so the entry paths of an archive together may not exceed the archive length; members beyond that are skipped with the same diagnostic. An archive without the `ustar` magic is recognised only under a `.tar` name, by its first header's checksum, or as an archive without members when it consists of zero blocks alone. Links, devices, FIFOs and directories are not listed.
- **LHA / LZH**: Parsed and decoded natively with no third-party decoder, from the format specification in `docs/lha/`. Entries are strictly sequential and a header is accepted only with a valid checksum or header CRC; nothing in a header is used as an offset. Every entry must decode to exactly its declared length and match its CRC-16, and nothing is delivered partially; a declared length that the packed bytes cannot produce is rejected before decoding for the stored, `-lh1-`, `-lzs-` and `-lz5-` methods. The static Huffman methods (`-lh4-` to `-lh7-`) can encode 16 MiB in seven bytes, so everything decoded from one archive, including entries that then fail their CRC and the second pass of the zero-window retry, is charged against a budget of 1024 times the bytes the archive's entries occupy, with no minimum, so nested archives cannot each claim an allowance; an entry whose declared length exceeds what is left is not decoded. Unsupported methods and entries failing any of these checks are skipped with a `ContainerEntriesSkipped` diagnostic while the readable entries are still listed.
- **ISO 9660 / UDF**: Parsed natively with no third-party reader. Directory nesting (32 levels for ISO 9660, 64 for UDF), the size of one directory (16 MiB) and of all directories together (the image size, at most 256 MiB) are bounded, directories are visited once, and everything copied out is charged against a budget of twice the image size (minimum 16 MiB), so entries that alias the same extents cannot multiply output. El Torito boot catalogs are read up to 1024 entries and their images are charged to the same budget; later sessions are searched for among at most 1024 candidate descriptor sets. In UDF every descriptor needs a valid tag checksum, CRC and location, and a file identifier's CRC may cover that descriptor only. Parsing ICBs, allocation extents, directories and the virtual allocation table, and looking up the blocks of a file's extents (one lookup per block on virtual and sparable partitions and in fragmented metadata files, whether or not the file turns out to be readable), is charged against a work budget of twice the image size, the search for the table tries at most 16 candidates, an allocation descriptor chain may not revisit a block, extents are read only up to the file's length, and a file's length is checked against the output budget before its extents are walked, so descriptors that alias, chain or loop cost time linear in the image size. Entries failing these checks are skipped with a `ContainerEntriesSkipped` diagnostic while the readable entries are still listed.
- **Unix compress**: Decoded natively with no third-party decoder, from the format specification in `docs/compress/`. The format carries no checksum, length or end marker, so its content is not authenticated and a truncated file is not detected. The output is measured in a first pass before any of it is allocated; a file with more than `MAX_DECOMPRESSED_SIZE` of output or with an invalid code is rejected as a whole, and nothing is delivered partially.
- **CUE/BIN**: Parsed natively with no third-party reader, from the format specification in `docs/cue/`. A sheet is at most 1 MiB of text with at most 99 `FILE` commands and track numbers 1 to 99. Track files are looked up only beside the sheet: an absolute path, a drive or a `..` component in a `FILE` name is never followed (only its base name is tried), and for a sheet on disk a link that leads out of the sheet's directory is not read. One track may not exceed `MAX_DECOMPRESSED_SIZE`, and all tracks of a sheet together may not exceed the size of the sheet and its track files (minimum 16 MiB, at most `MAX_DECOMPRESSED_SIZE`). Tracks failing these checks are skipped with a `ContainerEntriesSkipped` diagnostic while the readable tracks are still listed.
- **NeXT disk label / UFS**: Parsed natively with no third-party reader, from the format specifications in `docs/ufs/`. A label is accepted only with a valid checksum at one of its fixed positions; partitions are cut at the end of the image, and one that overlaps an earlier partition is left out. A UFS volume is accepted only when its superblock fields agree with each other and the root directory is where they say. The contents and paths of all listed files together are charged against a budget of twice the volume size (minimum 16 MiB, at most `MAX_DECOMPRESSED_SIZE`); at most 4,194,304 files and directories are listed, directories nest at most 64 levels and are entered once, and symbolic links are never followed. Files with blocks outside the volume are skipped with a `ContainerEntriesSkipped` diagnostic while the readable files are still listed.
- **Be File System**: Parsed natively with no third-party reader, from the format specification in `docs/bfs/`. Directory trees are walked by descent, each node once and at most 16 levels deep; directories nest at most 128 levels and are entered once, and symbolic links are never followed. File data, paths and 64 bytes per file together are charged against a budget of the image size (minimum 16 MiB), the directory trees read against a second budget of the same size, and no more i-nodes are read than the volume has blocks. A file whose block runs leave the volume or cover less than its size is not delivered, not even partially. Items failing these checks are skipped with a `ContainerEntriesSkipped` diagnostic while the readable files are still listed.
- **Apple Lisa**: Parsed natively with no third-party reader, from the format specifications in `docs/lisa/`, including the DiskCopy 4.2 and DART wrappers. A DiskCopy 4.2 header must agree with the file's length (also for Macintosh images); its checksums are not verified. A DART image with a chunk that does not decode is rejected. All files together, and the decoded DART image, are charged against a budget of twice the image size (minimum 16 MiB); reading entries that turn out unreadable is bounded by four times the volume's blocks, catalog chains are followed once and directory chains at most 16 levels. Files failing these checks are skipped with a `ContainerEntriesSkipped` diagnostic while the readable files are still listed.
- **Compression ratio checks**: RAR archives enforce a maximum compression ratio to block decompression bombs, including for entries with only a few packed bytes. In a solid archive the ratio is that of a solid group as a whole, since a file that repeats earlier files of its group legitimately packs to almost nothing; every file is still bounded by `MAX_DECOMPRESSED_SIZE`.
- **Path sanitisation**: All archive entry paths are sanitised to prevent directory traversal (`../`, absolute paths, null bytes).
- **No shell execution**: The library never invokes external processes or shells.
- **No file I/O in core**: The core library operates on in-memory byte slices; only the optional mmap path reads from the filesystem.

### Known Limitations

- RAR header parsing, the RAR 2.9 filter programs and the RAR 5 decoder are vendored from a third-party crate (`rar-stream`). Vulnerabilities in that code may affect unretro.
- The library does not validate cryptographic signatures or checksums beyond what the underlying format parsers provide.
